T6  RESOLVED 2026-08-22. Relationship between the two 15 Aug offload sets.

    FINDING: REUSED INDEX, not a same-file mismatch. The two sets are entirely
    disjoint -- no file in 173207 matches any file in 184714.

    Erase semantics, read from firmware source:
      - createLogFile() (firmware/03_ranging/03_initiator/03_initiator.ino, the
        "choose next boot_seq" scan) enumerates SPIFFS for pucklog_<board>_*.csv,
        takes the highest numeric index N, and opens N+1. Indices are monotonic
        only for as long as the earlier files remain on SPIFFS.
      - The FORMAT command handler calls SPIFFS.format(), which erases every file.
        After a FORMAT the scan finds nothing, so the next boot opens index 1 again.
      - One boot = one file, opened "w" and appended until power-off; a later boot
        never reopens an earlier index. A file therefore cannot shrink in place.

    Evidence:
      - 173207 file 1 = 3161 B, file 2 = 3161 B.
        184714 file 1 = 3161 B, file 2 = 2741 B, file 3 = 3161 B.
      - MD5 cross-check of all 15 files across both sets: NO pair matches.
        173207/file1 and 184714/file1 are the same SIZE but different CONTENT
        (first SUCCESS row 30.2434 m vs 32.8576 m).
      - File 2 shrinking 3161 -> 2741 B at the same index is impossible without an
        erase, per the semantics above.
      - Both sets begin at the 30 m marker (173207: medians 29.3 m, 61.5 m;
        184714: 32.0 m, 59.5 m), so 184714 is a restart of the sweep, not a
        continuation of it.

    boot_seq to 1. CANONICAL SET = 20260815_184714-Initiator (13 files, the complete
